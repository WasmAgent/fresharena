Core Research Question

Do the same solvers rank significantly differently on fixed public tasks vs. fresh generated tasks?

Why FreshArena?

Instead of testing agents on a fixed set of public problems, FreshArena generates fresh task instances from versioned task families, evaluates submissions with deterministic verifier packages, and runs submit-then-test adversarial checks after the solver commits its answer.

🔄 Dynamic Generation

Generate fresh task instances on-demand from versioned task families, preventing overfitting to fixed benchmarks.

✓ Deterministic Verification

Every submission is evaluated with verified, deterministic checker packages that produce consistent, reproducible results.

⚔️ Adversarial Testing

Submit-then-test protocol finds counterexamples and potential vulnerabilities in solver implementations.

📊 Complete Provenance

FAEP records capture the entire evaluation chain: task spec, solver metadata, verifier version, and score vectors.

🔬 Reproducible Science

One-command reproduction of published results with full environment specification and deterministic execution.

🎯 Task Families

First release focuses on JSON transformation tasks to study overfitting in coding agent evaluation.

Quick Start

1

Install FreshArena

Clone the repository and install dependencies:

git clone https://github.com/WasmAgent/fresharena.git
cd fresharena
bun install
2

Run a Non-LLM Baseline

Execute a baseline evaluation without API keys:

bun run fresharena run examples/non-llm-baseline
3

Replay Recorded Evaluations

Examine existing evaluation records:

bun run fresharena replay records/samples/sample-run.jsonl
4

Verify Task Implementations

Validate verifier implementations for task families:

bun run fresharena verify worlds/json-transform

Evaluation Tracks

FreshArena supports multiple evaluation methodologies to study different aspects of coding agent performance:

  • Model-Fixed: Compare agent workflow and prompt strategies with fixed models
  • Model-Open: Compare full product capability with any available model
  • Non-LLM Baseline: Reproducible lower bound without API costs
  • Budget-Normalized: Compare cost efficiency with fixed compute budgets

FAEP Record Format

Each evaluation produces a FAEP (FreshArena Evaluation Protocol) record — a signed, replayable JSONL artifact containing complete provenance:

  • • Task specification and seed hash
  • • Solver metadata and workflow hash
  • • Generator and tester metadata
  • • Verifier version and result hash
  • • Score vector (canonical/hidden/adversarial/immunity)
  • • Replay command and log hash
